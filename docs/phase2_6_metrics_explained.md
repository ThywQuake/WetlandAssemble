# Phase 2.6 统计量说明

这份文档专门解释 Phase 2.6 里几个核心统计量是什么意思、怎么读、容易误解的地方是什么。

目标是：**不看代码，也能大概知道这些 `.nc` 文件里的数值在表达什么。**

---

## 1. Phase 2.6 在做什么？

Phase 2.6 不是重新从原始数据开始处理，而是直接复用已经做好的 `0.25°` 粗分辨率缓存结果。

简单说，它做了两件事：

1. 把每个数据集在同一个网格上的湿地百分比拿出来
2. 先用 `GLWD v2` 当前有效范围做统一 landmask，再在这些数据集之间做“平均”和“离散程度”统计

这里**不包含 GWD30**，因为 GWD30 目前走的是另一条专门的数据路径，还没有接入这一步的统一缓存分析流程。

---

## 2. 输入和输出分别是什么？

### 输入

输入是每个数据集已经算好的 `0.25°` 湿地百分比缓存：

- 每个格点都有一个 `0~1` 的值
- `0` 表示这个格点基本不是湿地
- `1` 表示这个格点几乎完全是湿地

比如某个格点值是 `0.65`，可以通俗理解为：

> 这个 `0.25° × 0.25°` 网格里，大约有 `65%` 的面积被认为是湿地。

### 输出

Phase 2.6 主要输出两个 NetCDF：

- `phase2_6_stack_*.nc`
- `phase2_6_metrics_*.nc`

其中真正做分析时最常看的，是 `phase2_6_metrics_*.nc` 里的几个变量。

这里还有一个很重要但容易忽略的前提：

- 统计不是在“所有经纬网格”上直接做
- 而是先用 **`GLWD v2` 当前有效范围** 作为统一 landmask
- 也就是说，`GLWD` 没有定义的海洋区域，不会继续保留其他数据集的值

这样做的目的很直接：

> 有些数据集会在海洋上出现明显不合理的非空值，这些值不应该进入最终统计。

另外，Phase 2.6 现在还有一个**口径拆分**：

- `mean_wetland_fraction`：仍然看所有已加载数据集的平均
- `std_wetland_fraction` 和 `participant_count`：**不再包含**
  - `berkeley_rwawc`
  - `g2017`
  - `glwd_v2`

原因是这三个数据集的产品性质和另外几套动态粗尺度湿地百分比产品不完全一致，不适合作为 Rough 尺度 `std` 分歧度量的参与者。

---

## 3. 这些统计量分别是什么意思？

Phase 2.6 目前有 3 个核心统计量：

- `mean_wetland_fraction`
- `std_wetland_fraction`
- `participant_count`

其中最重要的两项通常是：

- 平均值：`mean_wetland_fraction`
- 分歧程度：`std_wetland_fraction`

---

## 4. `mean_wetland_fraction`：平均湿地百分比

### 它是怎么来的？

把所有已加载数据集在同一个格点上的湿地百分比直接求平均。

例如某个格点：

- 数据集 A = `0.80`
- 数据集 B = `0.60`
- 数据集 C = `0.10`

那么：

- `mean_wetland_fraction = (0.80 + 0.60 + 0.10) / 3 = 0.50`

### 它表示什么？

它表示：

> “综合这些数据集的结果，这个格点平均来看有多少比例像是湿地。”

### 怎么理解？

- 值越大，说明多数数据集都认为这里湿地面积比较大
- 值越小，说明多数数据集都认为这里湿地面积比较小

### 它的局限

它**不直接表示一致性**。

比如下面两种情况，平均值都可能是 `0.50`：

#### 情况 A：大家都差不多

- A = `0.48`
- B = `0.52`
- C = `0.50`

#### 情况 B：分歧很大

- A = `1.00`
- B = `0.00`
- C = `0.50`

所以：

> `mean_wetland_fraction` 更像“平均水平”，不是“分歧大小”。

---

## 5. `std_wetland_fraction`：湿地百分比标准差

### 为什么改用标准差？

因为 Phase 2.6 的输入本来就是**连续湿地百分比**，而不是离散类别。

这时如果先把它们硬切成“湿地 / 非湿地”，会丢掉很多信息。

标准差的优点是：

> 它直接衡量“这些数据集的湿地百分比彼此差得有多远”。

不需要先二值化。

### 它是怎么来的？

对同一个格点，把 **适合 Rough 尺度 std 比较的那部分数据集** 的湿地百分比做标准差。

目前会排除：

- `berkeley_rwawc`
- `g2017`
- `glwd_v2`

例如某个格点：

- A = `0.80`
- B = `0.60`
- C = `0.10`

平均值是 `0.50`，但这三个值彼此差得比较远，所以标准差会比较大。

如果换成：

- A = `0.48`
- B = `0.52`
- C = `0.50`

平均值还是 `0.50`，但它们彼此很接近，所以标准差会很小。

### 它表示什么？

它表示：

> “各个数据集对这个格点的湿地面积估计，到底分散得厉不厉害。”

### 怎么理解？

- `std_wetland_fraction` 小：大家估计很接近
- `std_wetland_fraction` 大：大家估计差异明显

### 它的范围大概是什么？

因为输入值都在 `0~1` 之间，所以标准差也会落在一个有限范围里。

直观上：

- 接近 `0`：几乎没有分歧
- 越大：说明差异越明显

在极端情况下，如果一部分数据集给 `0`，另一部分给 `1`，标准差会非常高。

### 为什么它比香农熵更适合这里？

因为标准差保留了连续信息。

举个最典型的例子：

#### 例 1：差一点点

- A = `0.49`
- B = `0.51`

#### 例 2：差很多

- A = `0.01`
- B = `0.99`

如果先用 `0.5` 做二值化，这两种情况都会变成：

- 一个投“非湿地”
- 一个投“湿地”

这样就看不出“差一点”和“差很多”的区别。

但标准差能把这两种情况明显区分开。

所以对 **连续湿地百分比** 来说：

> 标准差比香农熵更自然，也更少丢信息。

---

## 6. `participant_count`：有效参与数据集数

### 它是怎么来的？

有些格点不是每个数据集都有值。

比如：

- 某个数据集在这个区域没有覆盖
- 某个格点是 `NaN`
- 某个处理中间步骤把这个格点裁掉了

这时就要记录：

> 这个格点到底有几个数据集真正参与了统计

这里的“参与”现在特指：

> 参与 `std_wetland_fraction` 计算的数据集数

也就是说，`participant_count` 现在和 `std_wetland_fraction` 使用的是同一套参与者口径。

### 它表示什么？

它表示：

> “这个格点上的统计结果是基于几个数据集算出来的。”

### 怎么理解？

- 值大：统计更稳一些
- 值小：统计更脆弱，解释要小心

比如：

- `participant_count = 7`：说明 7 个数据集都在这个格点上有有效值
- `participant_count = 2`：说明只有 2 个数据集参与
- `participant_count = 1`：几乎没法谈“跨数据集差异”

所以这个量非常重要，因为它告诉你：

> 一个格点上的高标准差，到底是不是建立在足够多的数据集之上。

---

## 7. 这几个量应该怎么配合理解？

最推荐的读法是把它们放在一起看。

### 情况 1：平均值高，标准差低

说明：

- 大家都觉得这里湿地很多
- 而且估计值彼此接近

这是“稳定湿地区”。

### 情况 2：平均值低，标准差低

说明：

- 大家都觉得这里不是湿地
- 而且意见比较一致

这是“稳定非湿地区”。

### 情况 3：平均值中等，标准差高

说明：

- 综合起来既不算特别湿，也不算特别干
- 但不同数据集给出的湿地比例差异很大

这是最值得关注的“争议区”。

## 8. 常见误解

### 误解 1：平均值高就说明一致性高

不一定。

平均值高只说明整体偏湿，不说明大家是否彼此接近。

### 误解 2：标准差高就说明这里一定是湿地

不对。

标准差高只说明：

> 各数据集给出的湿地比例差得很大

它不说明这里最终偏向湿地还是非湿地。

这个要结合 `mean_wetland_fraction` 一起看。

### 误解 3：`participant_count` 不重要

其实很重要。

如果某个格点只有 2 个数据集参与，那它的高标准差和低标准差都要谨慎解释，因为样本太少。

---

## 9. 一个最简单的实战读图方法

如果你拿到 `phase2_6_metrics_*.nc`，可以按下面这个顺序理解：

### 第一步：先看 `participant_count`

确认这个格点是不是有足够多的数据集参与。

### 第二步：看 `std_wetland_fraction`

判断这里是不是高分歧区域。

### 第三步：看 `mean_wetland_fraction`

判断综合起来湿地面积大概有多高。

---

## 10. 一句话总结

如果只记一句话，可以记这个：

> `mean_wetland_fraction` 看“平均有多湿”，`std_wetland_fraction` 看“彼此差得有多大”，`participant_count` 看“有多少数据集参与了统计”。
